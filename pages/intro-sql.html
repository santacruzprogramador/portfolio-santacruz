Guía Teórica de SQL

¿Qué es el modelo relacional (SQL)?

Leer explicación

SQL (Structured Query Language)

Definición:
SQL es un lenguaje estándar para gestionar y manipular bases de datos relacionales. Permite organizar los datos en tablas con filas y columnas y seguir un esquema bien definido que establece cómo deben organizarse. Con SQL se pueden realizar operaciones como consultas, inserciones, actualizaciones y eliminaciones de datos.

Características principales:

  1. Modelo relacional: Trabaja con tablas, filas y columnas.
  2. Esquema fijo: La estructura de los datos debe estar predefinida.
  3. Operaciones estándar: Permite crear, leer, actualizar y eliminar datos.
  4. Lenguaje universal: SQL es usado en la mayoría de los sistemas de gestión de bases de datos relacionales (RDBMS).
  5. Consultas complejas: Permite unir tablas, filtrar, agrupar y ordenar información.

¿Cuál es la historia de SQL?

Leer explicación

SQL fue desarrollado en la década de 1970 por IBM como parte del proyecto System R. Se basó en los principios de las bases de datos relacionales propuestos por Edgar F. Codd.

- En 1986, se convirtió en un estándar oficial de ANSI.
- En 1987, fue aprobado por la ISO.

¿Para qué sirve SQL?

Leer explicación

SQL es fundamental para la administración de bases de datos. Se utiliza para:

- Recuperar información específica.
- Administrar estructuras de datos como tablas y relaciones.
- Controlar accesos y permisos.

Es ampliamente usado en aplicaciones empresariales, sitios web y análisis de datos.

¿Qué tipos de sistemas gestores de bases de datos (SGBDs) existen?

Leer explicación

Un gestor SQL o Sistema Gestor de Bases de Datos (SGBD) es un software que permite crear, administrar y manipular bases de datos mediante el lenguaje SQL (Structured Query Language). Su función principal es facilitar el almacenamiento, consulta y modificación eficiente de la información.

Algunos de los SGBDs más utilizados son:

  • MySQL: Popular en aplicaciones web por su rapidez y facilidad de uso.
  • PostgreSQL: Muy completo y compatible con estándares avanzados de SQL.
  • Microsoft SQL Server: Usado en entornos empresariales de Microsoft.
  • Oracle Database: Ideal para grandes volúmenes de datos y alto rendimiento.
  • SQLite: Ligero y sin servidor, común en aplicaciones móviles.
  • MariaDB: Derivado de MySQL, con mejor rendimiento y seguridad.

¿Cuáles son los tipos de datos en SQL?

Leer explicación

En SQL, los principales tipos de datos son:

  • VARCHAR: Cadena de texto variable, con una longitud máxima especificada.
  • CHAR: Cadena de texto fija, con una longitud específica.
  • INT: Número entero, positivo o negativo.
  • BIGINT: Número entero grande.
  • FLOAT: Número decimal de precisión simple.
  • DOUBLE: Número decimal de doble precisión.
  • DECIMAL: Número decimal con precisión fija.
  • BLOB: Objeto binario grande para almacenar datos binarios.
  • DATE: Fecha (año, mes y día).
  • TIME: Hora (horas, minutos y segundos).
  • DATETIME: Fecha y hora combinadas.
  • TIMESTAMP: Marca de tiempo específica.
  • BOOLEAN: Valor verdadero o falso.
  • BIN: Datos binarios como imágenes o archivos.
  • JSON: Datos estructurados en formato JSON.

¿Qué tipos de sentencias existen en SQL?

Leer explicación

En SQL, las sentencias se dividen en categorías según la función que cumplen dentro de una base de datos. Esta clasificación permite organizar el lenguaje de manera clara y facilitar su uso en distintas operaciones.

Principales divisiones:

  • Data Definition Language (DDL) Estas sentencias se utilizan para definir y modificar la estructura de la base de datos. Ejemplos:
    • CREATE: Crea bases de datos, tablas o vistas.
    • ALTER: Modifica la estructura de una tabla (agregar o eliminar columnas, cambiar tipos de datos, etc.).
    • DROP: Elimina tablas, vistas o bases de datos.
    • TRUNCATE: Borra todos los registros de una tabla, pero mantiene su estructura.
  • Data Manipulation Language (DML) Son sentencias que permiten trabajar directamente con los datos dentro de las tablas. Ejemplos:
    • SELECT: Consulta y obtiene datos.
    • INSERT: Inserta nuevos registros.
    • UPDATE: Actualiza registros existentes.
    • DELETE: Elimina registros.
  • Data Control Language (DCL) Sirven para gestionar los permisos y accesos de los usuarios a la base de datos. Ejemplos:
    • GRANT: Concede permisos a los usuarios.
    • REVOKE: Revoca permisos otorgados.
  • Transaction Control Language (TCL) Se utilizan para manejar transacciones, asegurando que las operaciones sobre los datos sean consistentes. Ejemplos:
    • COMMIT: Confirma los cambios realizados en la base de datos.
    • ROLLBACK: Revierte los cambios si ocurre un error.
    • SET TRANSACTION: Define propiedades para una transacción.

En resumen: Las sentencias se dividen de esta forma porque cada grupo cumple un propósito distinto: definir estructuras (DDL), manipular datos (DML), controlar accesos (DCL) y asegurar la integridad en operaciones (TCL).

¿Cuáles son los comandos y funciones básicas en SQL?

Leer explicación

Comandos principales:

  • SELECT: Recupera datos de una o varias tablas.
  • INSERT: Agrega nuevos datos a una tabla.
  • UPDATE: Actualiza los datos existentes en una tabla.
  • DELETE: Elimina datos de una tabla.
  • CREATE: Crea una nueva tabla, vista o índice.
  • ALTER: Modifica la estructura de una tabla existente.
  • DROP: Elimina una tabla, vista o índice.
  • GRANT: Concede permisos a usuarios.
  • REVOKE: Retira permisos concedidos.
  • JOIN: Une datos de varias tablas en base a una columna común.
  • UNION: Combina resultados de múltiples consultas.
  • GROUP BY: Agrupa resultados en base a columnas.
  • HAVING: Filtra resultados agrupados.
  • ORDER BY: Ordena resultados por columnas.
  • LIMIT: Limita la cantidad de filas devueltas.

Funciones más usadas:

  • AVG(): Promedio de una columna numérica.
  • COUNT(): Número de filas o valores distintos.
  • MAX(): Valor máximo de una columna.
  • MIN(): Valor mínimo de una columna.
  • SUM(): Suma de valores de una columna.
  • CONCAT(): Combina cadenas de texto.
  • UPPER(): Convierte a mayúsculas.
  • LOWER(): Convierte a minúsculas.
  • LEFT(): Devuelve los primeros caracteres de un texto.
  • RIGHT(): Devuelve los últimos caracteres de un texto.
  • DATE(): Extrae valores de fecha y hora.
  • YEAR(): Devuelve el año de una fecha.
  • MONTH(): Devuelve el mes de una fecha.
  • DAY(): Devuelve el día de una fecha.
  • ROUND(): Redondea valores numéricos.

-- Preparando la BD para nuevos temas

-----------------------------------------------------------
-- Operaciones de administración de usuarios
-----------------------------------------------------------



-- Crear un usuario 'usuario_1' para el host 'localhost' con la contraseña 'qwerty'.

CREATE USER 'usuario_1'@'localhost' IDENTIFIED BY 'qwerty';


-- (Opción adicional) Crear un usuario para acceso remoto: 
-- Esto permite conexiones desde cualquier host ('%') en lugar de solo localhost.

CREATE USER 'usuario_remoto'@'%' IDENTIFIED BY 'qwerty';


-- Asignar privilegios al usuario 'usuario_1' sobre la base de datos 'curso_sql'.
-- Esto es esencial para que el usuario pueda realizar operaciones sobre dicha base de datos.

GRANT ALL PRIVILEGES ON curso_sql.* TO 'usuario_1'@'localhost';


-- Actualizar los privilegios aplicados en el servidor MySQL.

FLUSH PRIVILEGES;


-- Mostrar los privilegios asignados al usuario "usuario_1".

SHOW GRANTS FOR 'usuario_1'@'localhost';


-- Revocar todos los privilegios asignados al usuario 'usuario_1'.

REVOKE ALL PRIVILEGES ON curso_sql.* FROM 'usuario_1'@'localhost';

-- Eliminar el usuario 'usuario_1' de forma segura.
DROP USER IF EXISTS 'usuario_1'@'localhost';

-- Eliminar múltiples usuarios de una sola vez.
DROP USER IF EXISTS 'usuario_1'@'localhost', 'usuario_remoto'@'localhost';

-- Consultar la tabla interna 'mysql.user' para mostrar usuarios y hosts.
SELECT User, Host FROM mysql.user;

-- Mostrar el usuario autenticado en la sesión actual.
SELECT USER();  

-- Mostrar el usuario que MySQL usa para la autenticación y permisos.
SELECT CURRENT_USER();

    user_id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,     -- Identificador único del perfil, autoincremental

    email VARCHAR(50) UNIQUE,                            -- Correo electrónico, debe ser único
    address VARCHAR(100) DEFAULT 'No address',           -- Dirección, valor por defecto si no se especifica

);

CREATE TABLE usuarios (
    nombre VARCHAR(30),        -- Nombre del usuario
    correo VARCHAR(30),        -- Correo electrónico del usuario
    contraseña INT             -- Contraseña del usuario (se recomienda usar un tipo de dato más seguro, como VARCHAR o HASH)
);

-- Tabla para almacenar los productos disponibles en la tienda

    name VARCHAR(50),         -- Nombre del producto
    description TEXT,         -- Descripción detallada del producto
    price DECIMAL(10,2),      -- Precio del producto con dos decimales
    stock INT                 -- Cantidad de unidades disponibles en inventario
);

-- Tabla para registrar las órdenes de compra realizadas por los usuarios
CREATE TABLE orden (
    quantity INT,             -- Cantidad de productos en la orden
    tracking_number VARCHAR(50) -- Número de seguimiento del pedido
);

----------------------------------------------------------------
-- Operador LIKE
----------------------------------------------------------------

-- Buscar empleados cuyo nombre empieza con "Juan"
SELECT * FROM empleados
WHERE nombre LIKE 'Juan%';  -- El % permite cualquier cosa después de "Juan"

-- Buscar empleados cuyo nombre termina con "Gómez"
SELECT * FROM empleados
WHERE nombre LIKE '%Gómez';  -- El % permite cualquier cosa antes de "Gómez"

-- Buscar empleados cuyo nombre contiene "José" en cualquier parte
SELECT * FROM empleados
WHERE nombre LIKE '%José%';  -- El % permite cualquier cosa antes o después de "José"

-- Buscar empleados cuyo nombre tiene "a" en la segunda posición
SELECT * FROM empleados
WHERE nombre LIKE '_a%';  -- _ representa cualquier carácter en la primera posición, luego "a", seguido de cualquier cosa

----------------------------------------------------------------
-- Operador NOT LIKE
----------------------------------------------------------------

-- Buscar empleados cuyo nombre no empieza con "Juan"
SELECT * FROM empleados
WHERE nombre NOT LIKE 'Juan%';  -- El % permite cualquier cosa después de "Juan", pero excluye esos nombres

-- Buscar empleados cuyo nombre no termina con "Gómez"
SELECT * FROM empleados
WHERE nombre NOT LIKE '%Gómez';  -- El % permite cualquier cosa antes de "Gómez", pero excluye esos nombres

-- Buscar empleados cuyo nombre no contiene "José" en cualquier parte
SELECT * FROM empleados
WHERE nombre NOT LIKE '%José%';  -- El % permite cualquier cosa antes o después de "José", pero excluye esos nombres

-- Buscar empleados cuyo nombre no sigue el patrón "J" seguido de un solo carácter y luego "án"
SELECT * FROM empleados
WHERE nombre NOT LIKE 'J_án';  -- _ es un comodín que representa un solo carácter en el medio, excluye esos nombres

----------------------------------------------------------------
-- Operadores relacionales
----------------------------------------------------------------

-- Buscar empleados cuya edad es diferente de 38 (uso del operador !=)
SELECT * FROM empleados WHERE edad != 38;  -- != es equivalente a "<>", ambas formas comparan si la edad es diferente de 38

-- Buscar empleados cuya edad es diferente de 38 (uso del operador <>)
SELECT * FROM empleados WHERE edad <> 38;  -- <> es el operador estándar en SQL para comparar "diferente de"

-- Buscar empleados cuya edad es exactamente 38
SELECT * FROM empleados WHERE edad = 38;  -- = compara si la edad es exactamente igual a 38

-- Buscar empleados cuya edad es mayor que 38
SELECT * FROM empleados WHERE edad > 38;  -- > compara si la edad es mayor que 38

-- Buscar empleados cuya edad es mayor o igual a 38
SELECT * FROM empleados WHERE edad >= 38;  -- >= compara si la edad es mayor o igual a 38

-- Buscar empleados cuya edad es menor que 38
SELECT * FROM empleados WHERE edad < 38;  -- < compara si la edad es menor que 38

-- Buscar empleados cuya edad es menor o igual a 38
SELECT * FROM empleados WHERE edad <= 38;  -- <= compara si la edad es menor o igual a 38

----------------------------------------------------------------
-- Operadores Lógicos
----------------------------------------------------------------

-- Buscar empleados cuyo salario es mayor a 4000 y que pertenezcan al departamento 'Marketing'
SELECT * FROM empleados 
WHERE salario > 4000 AND departamento = 'Marketing'; 
-- El operador AND se usa para que ambas condiciones sean verdaderas

-- Buscar empleados que tienen un salario menor a 4500 o que pertenecen al departamento 'TI'
SELECT * FROM empleados 
WHERE salario < 4500 OR departamento = 'TI'; 
-- El operador OR se usa para que al menos una de las condiciones sea verdadera

-- Buscar empleados que no pertenezcan al departamento 'Ventas'
SELECT * FROM empleados 
WHERE NOT departamento = 'Ventas'; 
-- El operador NOT se usa para negar una condición. En este caso, excluye a los empleados del departamento 'Ventas'

-- Buscar empleados cuyo salario está entre 4000 y 5000 y que su edad sea mayor a 30
SELECT * FROM empleados 
WHERE salario BETWEEN 4000 AND 5000 AND edad > 30;
-- El operador BETWEEN se usa para verificar si un valor está dentro de un rango específico, en este caso salario entre 4000 y 5000

----------------------------------------------------------------
-- Sentencia UPDATE(se usa siempre con where, si no peligro)
----------------------------------------------------------------

-- Actualizar el salario de un empleado específico que tiene el ID 5
UPDATE empleados

WHERE id = 5;

-- Se actualiza el salario de todos los empleados en el departamento 'Ventas'. Sin WHERE, afectaría a todos los registros.

UPDATE empleados 
SET edad = 31 
WHERE nombre = 'Juan Pérez'; 
-- Se actualiza la edad de 'Juan Pérez'. Sin WHERE, modificaría a todos los empleados con el mismo nombre.

UPDATE empleados

WHERE edad > 30; 
-- Se incrementa el salario de todos los empleados mayores de 30 años en un 10%. La cláusula WHERE es necesaria para no afectar a todos los registros.

-------------------------------------------------------------

SELECT nombre, precio, MAX(precio) AS precio_maximo

GROUP BY precio, nombre;

Creación y Uso de Índices: Básicos, Únicos y Fulltext

Leer explicación

Los índices son estructuras de datos que mejoran la velocidad de las operaciones de recuperación de datos en las tablas. Funcionan como el índice de un libro, permitiendo que el motor de la base de datos encuentre rápidamente las filas sin tener que escanear toda la tabla.

  • Índices por Defecto: Se crean automáticamente al definir una columna como PRIMARY KEY o con la restricción UNIQUE.
  • Índices Básicos: Creados manualmente con INDEX i_nombre (columna) para optimizar la búsqueda en una columna específica.
  • Índices Compuestos: Se aplican a múltiples columnas, por ejemplo, INDEX i_compuesto (columna1, columna2), útiles para consultas que filtran por la combinación de esos campos.
  • Índices FULLTEXT: Diseñados para búsquedas de texto completo de alto rendimiento (MATCH...AGAINST) en grandes volúmenes de texto, superando a LIKE %...%.

El comando SHOW INDEX FROM tabla permite verificar los índices existentes, y EXPLAIN SELECT muestra si el optimizador está usando el índice correctamente.

JOINs, UNIONs, Subconsultas y Vistas

Leer explicación

Estos son algunos de los conceptos más importantes en el manejo de consultas SQL, que permiten relacionar, organizar y simplificar el acceso a los datos.

  • JOINs y UNIONs: Los JOINs permiten combinar datos de dos tablas en base a una relación común. El UNION se utiliza para unir los resultados de múltiples consultas en un solo conjunto.
  • JOINs de múltiples tablas: Se aplican cuando es necesario enlazar más de dos tablas en una sola consulta, obteniendo información relacionada de manera más compleja.
  • Subconsultas: Son consultas anidadas dentro de otra instrucción SQL que sirven para obtener valores intermedios o filtrar resultados.
  • Vistas: Son consultas almacenadas en la base de datos que funcionan como tablas virtuales, facilitando la reutilización y simplificación de consultas frecuentes.

Motores de Almacenamiento y Restricciones

Leer explicación

El Motor de Almacenamiento (cláusula ENGINE=) define las capacidades físicas de la tabla (ej. transacciones, soporte de claves foráneas). InnoDB es el motor estándar, ideal para datos transaccionales, mientras que MyISAM es más rápido para solo lectura. Las Restricciones de Integridad (FOREIGN KEY) definen cómo se manejan los datos cuando se elimina o actualiza un registro padre. Las opciones clave son RESTRICT (impide la acción, por defecto), CASCADE (propaga la acción) y SET NULL (establece la clave foránea a NULL).

MEMORY (HEAP): Almacena los datos en memoria RAM, ideal para consultas rápidas pero volátiles.

FEDERATED: Permite acceder a tablas en servidores remotos sin replicar los datos localmente.

Encriptación

Leer explicación

La Encriptación es un proceso que transforma los datos en un formato ilegible para proteger su confidencialidad. En SQL, se utiliza para resguardar información sensible, como contraseñas o datos financieros, mediante funciones que cifran y descifran la información, asegurando que solo usuarios autorizados puedan acceder a los datos originales. 

          

---------------------------------------------------------------------
-- Encriptación y Desencriptado en SQL
---------------------------------------------------------------------

/* La encriptación es un proceso de transformación de datos en un formato ilegible para proteger 
  la información contra accesos no autorizados. 

  En SQL, se utilizan funciones de encriptación para almacenar datos sensibles de manera segura. 
  Existen dos tipos principales de encriptación:
  
  1. **Encriptación Simétrica**: Usa la misma clave para cifrar y descifrar datos. 
    - Ejemplo: AES_ENCRYPT(), AES_DECRYPT() en MySQL.
  
  2. **Encriptación Asimétrica**: Usa una clave pública para cifrar y una privada para descifrar.

CREATE PROCEDURE sp_asignar_servicio(
  IN i_suscripcion INT UNSIGNED,
  IN i_nombre VARCHAR(30),
  IN i_correo VARCHAR(50),
  IN i_tarjeta VARCHAR(16),
  OUT o_respuesta VARCHAR(50)
)

  BEGIN

  DECLARE existe_correo INT DEFAULT 0;
  DECLARE cliente_id INT DEFAULT 0;
  DECLARE tarjeta_id INT DEFAULT 0;

  START TRANSACTION;

    SELECT COUNT(*) INTO existe_correo
      FROM clientes
      WHERE correo = i_correo;

    IF existe_correo <> 0 THEN

      SELECT 'Tu correo ya ha sido registrado' INTO o_respuesta;

    ELSE

      INSERT INTO clientes VALUES (0, i_nombre, i_correo);
      SELECT LAST_INSERT_ID() INTO cliente_id;

      INSERT INTO tarjetas
        VALUES (0, cliente_id, AES_ENCRYPT(i_tarjeta, cliente_id));
      SELECT LAST_INSERT_ID() INTO tarjeta_id;

      INSERT INTO servicios VALUES (0, cliente_id, tarjeta_id, i_suscripcion);

      SELECT 'Servicio asignado con éxito' INTO o_respuesta;

    END IF;

  COMMIT;

  END //
