Introducción a Programación Orientada a Objetos

¿Cuántos paradigmas de programación existen?

Leer explicación

Existen varios paradigmas de programación, cada uno con su enfoque y forma de estructurar el código. Los principales son:

  • Programación Imperativa: Se centra en instrucciones que cambian el estado del programa.
  • Programación Estructurada: Subtipo de la imperativa, usa bloques y estructuras de control claras como bucles y condicionales.
  • Programación Orientada a Objetos (POO): Organiza el código en clases y objetos, usando conceptos como herencia, encapsulación y polimorfismo.
  • Programación Funcional: Basada en funciones puras y evita estados mutables, promoviendo la inmutabilidad.
  • Programación Lógica: Basada en reglas y hechos, como en Prolog, donde se define el "qué" más que el "cómo".
  • Programación Declarativa: El programador describe el resultado deseado sin especificar paso a paso cómo lograrlo.

¿Qué es la programación POO?

Leer explicación

La programación orientada a objetos es la capacidad de desarrollar estructura de código legible, para que en el futuro sea sencillo escalarlo.

¿Beneficios de POO?

Leer explicación

La Programación Orientada a Objetos (POO) permite organizar el código en objetos que combinan datos y comportamientos, lo que facilita la reutilización de código, la escalabilidad de aplicaciones, el mantenimiento y el modelado de sistemas complejos de manera más intuitiva.

¿Qué es la abstracción?

Leer explicación

La abstracción consiste en ocultar los detalles complejos de la implementación y exponer únicamente lo esencial. Permite centrarse en lo que un objeto hace, en lugar de cómo lo hace, facilitando la comprensión y el uso del código.

Por ejemplo:

Cuando manejas un auto solo necesitas usar el volante, el acelerador y el freno, sin preocuparte por cómo funciona el motor, la transmisión o los sistemas internos; de la misma forma, en POO la abstracción permite usar un objeto a través de funciones simples sin necesidad de conocer la complejidad de su funcionamiento interno.

¿Qué es el encapsulamiento?

Leer explicación

Es el principio de la Programación Orientada a Objetos que controla el acceso a los atributos y métodos de una clase, definiéndolos como públicos, privados o protegidos. Su objetivo es proteger los datos internos y asegurar que solo puedan modificarse de manera controlada, evitando cambios directos desde otras clases.

Ejemplo práctico: Si una clase CuentaBancaria tiene un atributo saldo privado, solo se podrá modificar mediante métodos como depositar() o retirar(), evitando alterar la lógica interna de la clase.

Programación Orientada a Objetos en Python

Clases

Leer explicación

las clases son plantillas para crear objetos. Un objeto es una instancia de una clase. Las clases encapsulan datos y comportamientos relacionados, permitiendo la creación de estructuras de datos complejas y reutilizables. las clase tienen 3 componentes principales:

  • Nombre de la clase: Identifica al objeto (ejemplo: Auto, Persona).
  • Atributos (variables): Son las características o datos del objeto (ejemplo: color, edad, saldo).
  • Métodos (funcionalidades): Son las acciones que el objeto puede realizar (ejemplo: arrancar, hablar, depositar).

Ejemplo en Python

              
                #1) Nombre de la clase
                class Persona():
                    # Metodo constructor
                    def __init__(self): 
                        #2) Atributos(variables de instancia)                             
                        self._nombre = "" # Variable de instancia
                        self._edad = None # Variable de instancia 
                        
                    @property
                    def nombre(self):
                        return self._nombre
                    @nombre.setter
                    def nombre(self, valor):
                        self._nombre = valor
                    @nombre.deleter
                    def nombre(self):
                        del self._nombre
                        
                    @property
                    def edad(self):
                        return self._edad
                    @edad.setter
                    def edad(self, valor):
                        if valor < 0:
                            raise ValueError("La edad no puede ser negativa")
                        self._edad = valor
                    @edad.deleter
                    def edad(self):
                        del self._edad
                    
                    #3) Metodos (funcionalidades) 
                    def hablar(self, mensaje):
                        print(f"{self.nombre}: {mensaje}")
                        
                    def comer(self, alimento):
                        print(f"{self.nombre} esta comiendo {alimento}")

Abstracción

Leer explicación

No es necesario conocer cómo funciona internamente, solo cómo utilizarlo.

El programador únicamente necesita saber que, al invocar el método conducir, el objeto Auto realizará la acción de conducir.

La abstracción en Programación Orientada a Objetos (POO) consiste en ocultar la complejidad de la implementación y mostrar únicamente las funcionalidades esenciales que permiten interactuar con el objeto de forma sencilla y efectiva.

Ejemplo en Python

              
                class Auto:
                    def __init__(self):
                        self._estado = "apagado"

                    def encender(self):
                        self._estado = "encendido"
                        print("El auto está encendido")

                    def conducir(self):
                        if self._estado == "apagado":
                            self.encender()
                        print("Conduciendo el auto")

                # Ejemplo de uso
                if __name__ == "__main__":
                    mi_auto = Auto()
                    mi_auto.conducir()

Herencia(subclase, derivada)

Leer explicación

La herencia en Programación Orientada a Objetos (POO) es el mecanismo que permite a una clase (subclase o clase derivada) adquirir los atributos y métodos de otra clase (superclase o clase base). De esta forma, se promueve la reutilización del código y la creación de jerarquías que reflejan relaciones del mundo real.

Ejemplo en Python

              
                from persona import Persona
          
 
                # 1) Clase Deportista que hereda de la clase base Persona
                class Deportista(Persona):
                    # Método constructor de Deportista, con un atributo adicional 'deporte'
                    def __init__(self, nombre="", edad=None, deporte=""):

                        # Reutiliza el constructor de la superclase Persona para inicializar 'nombre' y 'edad'
                        super().__init__(nombre, edad)

                        # Atributo adicional específico del Deportista que indica el deporte que practica
                        self._deporte = deporte

                    # Propiedad 'deporte' para acceder al atributo privado '_deporte'
                    @property
                    def deporte(self):
                        return self._deporte

                    # Setter para modificar el valor de 'deporte'
                    @deporte.setter
                    def deporte(self, valor):
                        self._deporte = valor
                    
                    # Deleter para eliminar el valor de 'deporte'
                    @deporte.deleter
                    def deporte(self):
                        del self._deporte
                        
                    # Método que simula el entrenamiento del deportista en su deporte
                    def entrenar(self):
                        print(f"{self.nombre} está entrenando {self.deporte}")
                        
                    # Método especial __str__ para definir la representación en cadena del objeto
                    # Incluye la información heredada de Persona y el deporte del Deportista
                    def __str__(self):
                        return f"""
                {super().__str__()}
                Deporte: {self.deporte}"""

Herencia jerárquica

Leer explicación

La herencia jerárquica en POO ocurre cuando una única clase base (superclase) es extendida por varias clases derivadas (subclases), permitiendo que todas compartan atributos y métodos comunes, mientras cada subclase puede añadir sus propias características específicas; por ejemplo, una clase Animal podría tener subclases Perro, Gato y Ave que heredan sus propiedades generales pero implementan comportamientos particulares como ladrar() o volar().

Herencia múltiple

Leer explicación

La herencia múltiple en POO ocurre cuando una clase derivada hereda atributos y métodos de más de una clase base, permitiendo combinar funcionalidades de diferentes clases en una sola. 

            
              class Persona:
                  def __init__(self, nombre, edad, nacionalidad):
                      self.nombre = nombre
                      self.edad = edad
                      self.nacionalidad = nacionalidad

                  def hablar(self):
                      print("Hola, estoy hablando un poco")

              class Artista:
                  def __init__(self, habilidad):
                      self.habilidad = habilidad

                  def mostrar_habilidad(self):
                      print(f"Mi habilidad es: {self.habilidad}")

              # Herencia múltiple
              class EmpleadoArtista(Persona, Artista):
                  def __init__(self, nombre, edad, nacionalidad, habilidad, salario, empresa):
                      Persona.__init__(self, nombre, edad, nacionalidad)
                      Artista.__init__(self, habilidad)
                      self.salario = salario
                      self.empresa = empresa

                  def mostrar_habilidad(self):
                      print("no tengo jaja")

                  def presentarse(self):
                      return f"{super().mostrar_habilidad()}"

Polimorfismo

Leer explicación

El polimorfismo permite que un mismo método se comporte de manera diferente según la clase que lo implemente. En Python, esto significa que distintas clases pueden tener métodos con el mismo nombre, pero cada uno ejecuta su propia lógica.

Ejemplo práctico:

Un método atacar() en las clases Momia, Zombi y Vampiro realiza ataques distintos, aunque se llame igual.

Enemigo es una clase base que define los atributos y métodos comunes a todos los enemigos de un juego:

  • tipo: indica si es Momia, Zombi o Vampiro.
  • ataque: describe el ataque que realiza.
  • energia: cuánta energía tiene.
  • fuerza: cuánto daño puede causar.

La clase Enemigo tiene un método atacar() que imprime el ataque y el daño causado. Todas las clases derivadas pueden usar este método, pero cada una tiene sus propios valores de atributos.

Clases derivadas:

  • Momia: hereda de Enemigo y tiene ataque "Bendaje Sangriento", energía 12 y fuerza 8.
  • Zombi: hereda de Enemigo y tiene ataque "Zarpazo Violento", energía 15 y fuerza 12.
  • Vampiro: hereda de Enemigo, tiene ataque "Mordisco Letal", energía 12, fuerza 10 y un atributo extra recuperacion = 4.

Aunque todas usan el mismo método atacar(), cada enemigo se comporta diferente gracias al polimorfismo.

Encapsulamiento

Leer explicación

El encapsulamiento en Python es un principio de la Programación Orientada a Objetos (POO) que consiste en restringir el acceso directo a los atributos de un objeto. En lugar de acceder a los atributos directamente, se utilizan métodos especiales llamados getters y setters (propiedades con @property) para leer y modificar esos valores de forma segura.

Esto sirve para:

  • Proteger los datos de cambios no deseados.
  • Mantener la integridad del objeto.
  • Hacer que el uso de la clase sea más seguro y ordenado.
            

"""
Ejemplo de Encapsulamiento en Python
Niveles de acceso: público, protegido y privado.
"""



class Persona:
    def __init__(self, nombre, edad, dni):
        # Atributo público → se puede acceder libremente desde cualquier parte
        self.nombre = nombre  

        # Atributo protegido → convención: solo debe usarse dentro de la clase y subclases
        self._edad = edad      

        # Atributo privado → el intérprete aplica "name mangling"
        # para evitar accesos directos accidentales
        self.__dni = dni       

    # Getter para atributo privado
    def get_dni(self):
        return self.__dni

    # Setter con validación para atributo privado
    def set_dni(self, nuevo_dni):
        if isinstance(nuevo_dni, str) and nuevo_dni.isdigit():
            self.__dni = nuevo_dni
        else:
            print("DNI no válido.")

# ===================== EJEMPLO DE USO =====================
persona = Persona("Ana", 25, "12345678")

# Público → acceso directo permitido
print(persona.nombre)  # Ana

# Protegido → se puede acceder, pero no es recomendable hacerlo fuera de la clase
print(persona._edad)   # 25 (no está realmente protegido)

# Privado → no se puede acceder directamente (lanza AttributeError)
# print(persona.__dni)  # ❌ Error
# Acceso correcto mediante métodos (getters/setters)
print(persona.get_dni())  # 12345678
persona.set_dni("87654321")
print(persona.get_dni())  # 87654321

¿Cuáles son los 4 pilares de la Programación Orientada a Objetos (POO)?

Leer explicación

Los cuatro pilares de la Programación Orientada a Objetos (POO) son principios fundamentales que facilitan el diseño, la reutilización y el mantenimiento del software:

  • Abstracción: Ocultar los detalles internos y exponer solo lo necesario para usar un objeto.
  • Herencia: Reutilizar y extender comportamiento mediante la derivación de clases.
  • Encapsulación: Proteger y controlar el acceso a los datos mediante atributos y métodos con niveles de acceso.
  • Polimorfismo: Permitir que diferentes clases respondan a la misma interfaz o método de forma distinta.

¿Qué es el principio SOLID?

Leer explicación

El principio SOLID es un conjunto de cinco principios de diseño de software que tienen como objetivo hacer que el código sea más comprensible, flexible y fácil de mantener. Estos principios fueron propuestos por Robert C. Martin y son ampliamente utilizados en el desarrollo orientado a objetos (OOP), incluido Python.

SOLID es un acrónimo que representa los siguientes principios:

  1. S - Single Responsibility Principle (Principio de Responsabilidad Única):

    Una clase debe tener una única responsabilidad o razón para cambiar. En otras palabras, una clase debería encargarse de una única cosa.

  2. O - Open/Closed Principle (Principio Abierto/Cerrado):

    El código debe estar abierto para la extensión pero cerrado para la modificación. Esto significa que deberías poder agregar nuevas funcionalidades al código existente sin modificar el código ya escrito.

  3. L - Liskov Substitution Principle (Principio de Sustitución de Liskov):

    Los objetos de una clase derivada deben poder sustituir a objetos de la clase base sin alterar el comportamiento del programa.

  4. I - Interface Segregation Principle (Principio de Segregación de Interfaces):

    Los clientes no deberían estar obligados a depender de interfaces que no utilizan. Es mejor tener muchas interfaces pequeñas y específicas que una sola interfaz grande y general.

  5. D - Dependency Inversion Principle (Principio de Inversión de Dependencias):

    Las dependencias deben invertirse, es decir, las clases de alto nivel no deben depender de las clases de bajo nivel; ambas deben depender de abstracciones. Las abstracciones no deben depender de los detalles; los detalles deben depender de las abstracciones.

¿Qué es el formato JSON?

Leer explicación

JSON (JavaScript Object Notation) es un formato de texto ligero utilizado para el intercambio de datos entre aplicaciones. Es fácil de leer y escribir tanto para humanos como para máquinas, y permite representar estructuras de datos complejas como objetos, arreglos, números, cadenas de texto y valores booleanos. JSON se usa ampliamente en APIs, configuraciones y almacenamiento de datos, siendo compatible con la mayoría de los lenguajes de programación modernos.
