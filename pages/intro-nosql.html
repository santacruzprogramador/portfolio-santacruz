Introducción a NoSQL

¿Qué es NoSQL?

Leer explicación

NoSQL es un tipo de base de datos que no utiliza el modelo tradicional relacional basado en tablas. En lugar de eso, almacena los datos de forma más flexible, como en documentos, pares clave-valor, columnas anchas o grafos. Es ideal para manejar grandes volúmenes de datos no estructurados o semi-estructurados, ofreciendo escalabilidad horizontal y alto rendimiento.

Principales características:

  • Flexibilidad en los esquemas: No requiere una estructura fija, lo que permite almacenar datos heterogéneos.
  • Escalabilidad horizontal: Puede distribuirse fácilmente en varios servidores.
  • Alto rendimiento: Optimizado para lecturas y escrituras rápidas.
  • Compatibilidad con Big Data: Maneja grandes cantidades de datos y tráfico en tiempo real.

Tipos de bases de datos NoSQL:

  • Base de datos de documentos (e.g., MongoDB): Almacena datos en documentos JSON o similares.
  • Base de datos clave-valor (e.g., Redis): Guarda datos como pares clave-valor.
  • Base de datos de grafos (e.g., Neo4j): Representa datos como nodos y relaciones.
  • Base de datos de columnas anchas (e.g., Cassandra): Organiza los datos por columnas en lugar de filas.

Este tipo de base de datos es muy popular en aplicaciones modernas como redes sociales, IoT, análisis en tiempo real y sistemas distribuidos.

Ventajas y usos de NoSQL

Leer explicación

Ventajas de NoSQL:

  • Flexibilidad de esquema: No requiere una estructura fija de datos, lo que permite manejar datos heterogéneos o en constante cambio.
  • Escalabilidad horizontal: Se puede expandir fácilmente añadiendo más servidores en lugar de actualizar hardware existente.
  • Alto rendimiento: Optimizado para lecturas y escrituras rápidas, ideal para aplicaciones de alto tráfico.
  • Adecuado para Big Data: Maneja grandes volúmenes de datos y tráfico en tiempo real.
  • Distribución de datos: Los datos se distribuyen entre múltiples servidores, garantizando alta disponibilidad.
  • Variedad de modelos de datos: Incluye bases de datos clave-valor, documentos, grafos y columnas anchas, adaptándose a diferentes necesidades.

Usos comunes de NoSQL:

  1. Aplicaciones web y móviles: Ejemplo: redes sociales como Facebook o Instagram.
  2. Big Data y análisis en tiempo real: Ejemplo: recomendaciones en plataformas de streaming o comercio electrónico.
  3. IoT (Internet of Things): Ejemplo: almacenamiento de datos generados por dispositivos inteligentes.
  4. Sistemas de mensajería: Ejemplo: chats en tiempo real como WhatsApp o Slack.
  5. Sistemas de recomendación: Ejemplo: recomendaciones de productos en Amazon o Netflix.
  6. Análisis de grafos: Ejemplo: mapas de relaciones como los de LinkedIn o bases de datos de conocimiento.
  7. Gestión de contenido: Ejemplo: sitios web dinámicos con almacenamiento de contenido no estructurado (CMS).

Historia de NoSQL

Leer explicación

La historia de NoSQL comenzó como una respuesta a las limitaciones de las bases de datos relacionales tradicionales frente a las necesidades de las aplicaciones modernas.

  • Década de 1990:

    Se originaron sistemas orientados a objetos y de clave-valor para casos específicos. Un ejemplo temprano fue Lotus Notes.

  • 2000–2004:

    Con el auge de la web 2.0, surgieron grandes volúmenes de datos y nuevas necesidades de escalabilidad y rendimiento. Empresas tecnológicas desarrollaron sus propias soluciones:

    • Google desarrolló Bigtable (2004).
    • Amazon lanzó Dynamo (2007).
  • 2009:

    El término NoSQL fue acuñado por Johan Oskarsson durante una reunión en la que se presentaron sistemas no relacionales enfocados en la escalabilidad.

  • 2010 en adelante:

    Comenzaron a popularizarse bases de datos como MongoDB, Cassandra y Redis, impulsadas por la necesidad de manejar Big Data, datos no estructurados y aplicaciones distribuidas.

            
  <!-- Línea temporal simplificada de NoSQL -->
  1990s → Primeros sistemas clave-valor (Lotus Notes)
  2004  → Google Bigtable
  2007  → Amazon Dynamo
  2009  → Surge el término "NoSQL"
  2010+ → Popularización: MongoDB, Cassandra, Redis

Sistema Gestor de Bases de Datos NoSQL

Leer explicación

Un sistema gestor de bases de datos NoSQL es una plataforma de administración de datos no relacionales que permite almacenar, organizar y consultar información con estructuras flexibles. A diferencia de los sistemas relacionales (SQL), los gestores NoSQL están optimizados para manejar grandes volúmenes de datos distribuidos, ofrecer alta escalabilidad horizontal y soportar múltiples modelos de datos, como documentos, pares clave-valor, columnas o grafos.

Estos sistemas son ampliamente utilizados en aplicaciones que requieren baja latencia, alta disponibilidad y adaptabilidad del esquema, como redes sociales, motores de búsqueda o plataformas de comercio electrónico.

Principales gestores NoSQL

  • MongoDB – Orientado a documentos (JSON/BSON). Muy usado en aplicaciones web y móviles.
  • Cassandra – Basado en columnas distribuidas. Alta tolerancia a fallos y escalabilidad.
  • Redis – Almacenamiento en memoria tipo clave-valor. Ideal para caché y sesiones.
  • CouchDB – Orientado a documentos, con replicación sencilla y API RESTful.
  • Neo4j – Especializado en grafos, útil para redes sociales y análisis de relaciones.
  • Amazon DynamoDB – Servicio en la nube de AWS, clave-valor y documentos, totalmente gestionado.
  • HBase – Basado en columnas, construido sobre Hadoop, orientado a grandes volúmenes de datos.

Características clave de los gestores NoSQL

  • Escalabilidad horizontal: añadir nodos en lugar de depender de un único servidor.
  • Alta disponibilidad: replicación y tolerancia a fallos distribuidos.
  • Flexibilidad de esquema: no requieren estructuras fijas de tablas.
  • Optimización para Big Data: diseñados para manejar datos masivos y no estructurados.
  • Modelos de datos variados: documentos, grafos, clave-valor, columnas.

Key-Value: velocidad y simplicidad en acción

Leer explicación

Una base de datos NoSQL tipo Key-Value es un modelo de almacenamiento simple, rápido y eficiente, donde cada registro se guarda como un par clave-valor. Este enfoque es ideal para aplicaciones que requieren altas velocidades de lectura y escritura, baja latencia y una estructura flexible sin necesidad de esquemas rígidos.

Ejemplos de gestores Key-Value

  • Redis – Almacenamiento en memoria, ideal para caché, colas y sesiones.
  • Amazon DynamoDB – Servicio gestionado en la nube, soporta clave-valor y documentos.
  • Riak KV – Distribuido, con alta tolerancia a fallos.
  • Memcached – Caché en memoria, muy usado para acelerar aplicaciones web.
  • Berkeley DB – Librería embebida para almacenamiento clave-valor.

Casos de uso comunes

  • Caché de datos: sesiones de usuario, tokens de autenticación.
  • Configuración de aplicaciones: parámetros y preferencias.
  • Almacenamiento simple de objetos: perfiles, catálogos, listas de precios.
  • Colas y mensajería: claves como identificadores de tareas o mensajes.
  • Gaming y tiempo real: rankings, puntuaciones y estados de jugadores.

Características clave

  • Escalabilidad horizontal: fácil distribución en múltiples nodos.
  • Baja latencia: respuestas rápidas incluso con grandes volúmenes de datos.
  • Flexibilidad: el valor puede ser texto, JSON, binario u objetos complejos.
  • Simplicidad: modelo directo, sin necesidad de esquemas relacionales.

Document: flexibilidad de esquema y agilidad

Leer explicación

Una base de datos NoSQL tipo Document almacena registros como documentos (usualmente JSON/BSON), permitiendo esquemas flexibles y evolución rápida del modelo sin migraciones complejas. Es ideal para aplicaciones con estructuras heterogéneas y necesidad de iteración ágil.

Ejemplos de gestores Document

  • MongoDB: orientado a documentos (BSON), índices ricos y agregaciones.
  • Couchbase: documentos JSON con memoria y disco, vistas e índices.
  • Firestore (Google Cloud): documentos y colecciones con sincronización en tiempo real.
  • Amazon DocumentDB: compatible con API de MongoDB, servicio gestionado.

Casos de uso comunes

  • APIs web y móviles: payloads JSON naturales y versionado de campos.
  • Catálogos y perfiles: atributos variables por producto o usuario.
  • Contenido y CMS: entradas con estructuras dinámicas.
  • Event logging: documentos con metadata flexible.

Características clave

  • Esquema flexible: documentos con campos opcionales y anidados.
  • Indexación avanzada: índices compuestos, de texto y geoespaciales.
  • Agregaciones: pipelines para consultas analíticas sobre documentos.
  • Escalabilidad horizontal: partición por clave de documento.

Column-Family: rendimiento distribuido y control de acceso

Leer explicación

Una base de datos NoSQL tipo Column-Family organiza datos en familias de columnas, optimizadas para lecturas y escrituras distribuidas sobre grandes volúmenes. Los datos se particionan por clave de partición y se ordenan por columnas de clustering.

Ejemplos de gestores Column-Family

  • Apache Cassandra: alta disponibilidad y escalabilidad en clusters multi-datacenter.
  • Apache HBase: sobre Hadoop/HDFS, adecuado para grandes datasets y lectura secuencial.
  • ScyllaDB: compatible con CQL, orientado a baja latencia y alto throughput.

Casos de uso comunes

  • Time-series: métricas, logs y eventos con orden temporal.
  • IoT y telemetría: ingesta sostenida y consultas por rangos.
  • Analítica operativa: accesos por clave y scans eficientes.
  • Aplicaciones globales: replicación geográfica y tolerancia a fallos.

Características clave

  • Modelo wide-row: filas con muchas columnas y acceso por rangos.
  • Consistencia tunable: niveles configurables de lectura/escritura.
  • Particionamiento y clustering: diseño de claves para distribución y orden.
  • Compaction y SSTables: almacenamiento en disco optimizado para throughput.

Graph: relaciones primero, consultas expresivas

Leer explicación

Una base de datos NoSQL tipo Graph modela información como nodos, relaciones y propiedades. Prioriza la navegación de relaciones y consultas de conectividad sobre entidades densamente vinculadas.

Ejemplos de gestores Graph

  • Neo4j: grafo de propiedades con lenguaje Cypher.
  • Amazon Neptune: soporta RDF/SPARQL y TinkerPop/Gremlin.
  • JanusGraph: grafo distribuido sobre backends como Cassandra y HBase.

Casos de uso comunes

  • Redes sociales: recomendaciones basadas en relaciones y caminos.
  • Fraude y riesgo: detección de patrones y subgrafos sospechosos.
  • Supply chain: trazabilidad entre entidades conectadas.
  • Knowledge graphs: ontologías y consultas semánticas.

Características clave

  • Modelo de propiedades: nodos y aristas con atributos ricos.
  • Consultas de grafos: lenguajes como Cypher, Gremlin o SPARQL.
  • Traversal eficiente: exploración de relaciones profundas y caminos.
  • Flexibilidad: fácil evolución de relaciones sin esquemas rígidos.

Ejemplos de Empresas y Uso de Múltiples Bases de Datos NoSQL

Leer explicación

A continuación se muestran ejemplos de grandes empresas que utilizan diferentes tipos de bases de datos NoSQL para cubrir diversas necesidades técnicas, como escalabilidad, velocidad y modelado de datos. Cada tipo de base (Document, Key-Value, Column-Family o Graph) cumple un rol específico en su infraestructura.

  • Netflix:
    • Document: MongoDB para gestión de catálogos de películas.
    • Column-Family: Cassandra para manejo de datos escalables y replicación global.
    • Key-Value: Redis para caché y manejo de sesiones.
  • Facebook:
    • Graph: TAO (base propia) para modelar relaciones sociales.
    • Column-Family: Apache Cassandra para datos distribuidos y escalabilidad.
    • Key-Value: Memcached para acelerar el acceso a datos.
  • Uber:
    • Key-Value: Redis para caché de datos en tiempo real.
    • Document: MongoDB para almacenar datos de usuarios y viajes.
    • Column-Family: Cassandra para análisis a gran escala de datos de viajes.
  • Google:
    • Column-Family: Bigtable para datos analíticos y estructurados.
    • Graph: Grafos para servicios como Knowledge Graph y búsquedas contextuales.
    • Key-Value: DynamoDB para sistemas específicos en la nube.

Razón para Usar Múltiples Bases de Datos

Cada tipo de base de datos NoSQL resuelve problemas específicos relacionados con el rendimiento, la escalabilidad, la velocidad de acceso o la complejidad de las relaciones entre datos. Por eso, muchas empresas optan por combinar varios tipos de bases de datos para lograr un sistema más eficiente, rápido y adaptable a distintas necesidades.

Introducción a Redis - Key-Value (Clave-Valor)

Leer explicación

Redis no es un tipo de base de datos, sino un gestor de base de datos NoSQL que utiliza el modelo Key-Value (Clave-Valor) para almacenar la información. En este modelo, los datos se guardan en pares de clave y valor, donde la clave identifica de forma única el valor asociado. Redis se destaca por su alta velocidad, bajo tiempo de respuesta y su capacidad para manejar datos en tiempo real.

Modelo de Datos y Operaciones CRUD en Redis

Redis permite trabajar directamente desde la terminal o desde un servicio en la nube. A continuación, se muestran ejemplos de creación, lectura, actualización y eliminación de datos usando comandos tipo Key-Value: 

              
  # Crear registros de usuarios
  HSET user:1 name "John Doe" age 30 location "New York"
  HSET user:2 name "Jane Smith" age 25 location "London"

  # Agregar publicaciones de usuarios
  LPUSH user:1:posts 1001
  LPUSH user:1:posts 1002
  LPUSH user:2:posts 2001

  # Crear publicaciones
  HSET post:1001 content "¡Hola a todos!" created_at "2023-05-10 10:00:00" likes 10
  HSET post:1002 content "Feliz cumpleaños a mí" created_at "2023-05-09 15:30:00" likes 20
  HSET post:2001 content "¡Gran día en la playa!" created_at "2023-05-08 12:45:00" likes 15

  # Leer datos
  HGETALL user:1
  HGET user:1 name

  # Actualizar y eliminar datos
  HSET user:2 age 26
  DEL user:3
  HSET post:1002 likes 30
  DEL post:1003

Diferencia clave

Key-Value es el modelo de base de datos, mientras que Redis es el gestor que implementa ese modelo. En otras palabras: Redis es la herramienta que hace posible trabajar con bases de datos del tipo Key-Value.

Introducción a Apache Cassandra - Column-Family

Leer explicación

Apache Cassandra es un gestor de base de datos NoSQL que utiliza el modelo Column-Family. Este modelo permite manejar grandes volúmenes de datos distribuidos y escalables, ofreciendo alta disponibilidad sin un único punto de fallo. Cassandra es ideal para aplicaciones que requieren lecturas y escrituras rápidas en entornos de datos masivos y distribuidos.

Creando un servicio en la nube de Apache Cassandra

Cassandra puede desplegarse localmente o mediante servicios en la nube que ofrecen alta disponibilidad y replicación automática.

Modelo de datos y operaciones CRUD

Cassandra organiza los datos en keyspaces y tablas. A continuación, se muestra un ejemplo de creación de tablas y operaciones básicas: 

              
  HELP;
  DESC KEYSPACES;
  USE KEYSPACE_NAME;
  DESC TABLES;

  CREATE TABLE users (
    user_id UUID PRIMARY KEY,
    username TEXT,
    email TEXT,
    password TEXT,
    full_name TEXT
  );

  CREATE TABLE user_posts (
    user_id UUID,
    post_id UUID,
    post_content TEXT,
    created_at TIMESTAMP,
    PRIMARY KEY (user_id, post_id)
  );

  CREATE TABLE user_followers (
    user_id UUID,
    follower_id UUID,
    follower_username TEXT,
    PRIMARY KEY (user_id, follower_id)
  );

Modelo de datos y operaciones CRUD

            
      -- CREATE
      CREATE (:User {name: 'kEnAi', age: 10})

      -- READ
      MATCH (u:User {name: 'kEnAi'})
      RETURN u

      -- UPDATE
      MATCH (u:User {name: 'kEnAi'})
      SET u.age = 11

      -- DELETE
      MATCH (u:User {name: 'kEnAi'})
      DETACH DELETE u

      -- CREATE Movie
      CREATE (:Movie {title: 'Inception', genre: 'Thriller'})

      -- READ Movie
      MATCH (m:Movie {title: 'Inception'})
      RETURN m

      -- UPDATE Movie
      MATCH (m:Movie {title: 'Inception'})
      SET m.genre = 'Sci-Fi'

      -- DELETE Movie
      MATCH (m:Movie {title: 'Inception'})
      DETACH DELETE m

Características clave de Neo4j

  • Modelo de grafos de propiedades: nodos y relaciones con atributos.
  • Lenguaje Cypher: sintaxis declarativa para consultas de grafos.
  • Consultas de conectividad: patrones complejos de relaciones.
  • Escalabilidad: soporte para clusters y replicación.
  • Casos de uso: redes sociales, detección de fraude, recomendaciones, knowledge graphs.
