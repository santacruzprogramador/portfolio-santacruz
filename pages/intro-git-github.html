Guía Completa de GitHub - Teoría y Práctica

¿Qué es Git y GitHub?

Leer explicación

Git es un sistema de control de versiones distribuido que permite rastrear cambios en archivos y coordinar el trabajo entre múltiples personas. GitHub es una plataforma en la nube que aloja repositorios Git y facilita la colaboración.

Diferencias clave: Git funciona localmente en tu computadora, mientras que GitHub es un servicio web que almacena tus repositorios en línea y agrega características sociales como pull requests, issues y wikis.

Configuración inicial de Git

Leer explicación

Antes de usar Git, debes configurar tu identidad. Esta información se incluirá en cada commit que hagas. 

            
<!-- Configurar tu nombre de usuario -->
git config --global user.name "Tu Nombre"

<!-- Configurar tu correo electrónico -->
git config --global user.email "tuemail@ejemplo.com"

<!-- Verificar tu configuración -->
git config --list

Crear un nuevo repositorio local

Leer explicación

Un repositorio local es donde Git almacena el historial de versiones de tu proyecto en tu computadora. 

            
<!-- Crear una carpeta para tu proyecto -->
mkdir mi-proyecto
cd mi-proyecto

<!-- Inicializar un repositorio Git -->
git init

<!-- Esto crea una carpeta oculta .git que contiene todo el historial -->

Añadir y hacer commit de cambios

Leer explicación

El flujo básico de Git tiene tres áreas: Working Directory (archivos modificados), Staging Area (archivos preparados) y Repository (historial de commits). 

            
<!-- Crear un archivo -->
echo "# Mi Proyecto" > README.md

<!-- Ver estado de los archivos -->
git status

<!-- Añadir archivo al staging area -->
git add README.md

<!-- O añadir todos los archivos modificados -->
git add .

<!-- Hacer commit de los cambios -->
git commit -m "Primer commit: añadir README"

<!-- Ver historial de commits -->
git log

Conectar repositorio local con GitHub

Leer explicación

Para sincronizar tu repositorio local con GitHub, primero debes crear un repositorio en GitHub.com y luego conectarlo con tu repositorio local. 

            
<!-- Añadir repositorio remoto (origin es el nombre convencional) -->
git remote add origin https://github.com/tu-usuario/tu-repositorio.git

<!-- Verificar repositorios remotos configurados -->
git remote -v

<!-- Renombrar la rama principal a 'main' (convención actual) -->
git branch -M main

<!-- Subir tus cambios por primera vez -->
git push -u origin main

<!-- En futuros push solo necesitas -->
git push

Clonar un repositorio existente

Leer explicación

Clonar crea una copia completa de un repositorio remoto en tu máquina local, incluyendo todo el historial de commits. 

            
<!-- Clonar repositorio con HTTPS -->
git clone https://github.com/usuario/repositorio.git

<!-- Clonar con SSH (requiere configurar llaves SSH) -->
git clone git@github.com:usuario/repositorio.git

<!-- Clonar en una carpeta con nombre específico -->
git clone https://github.com/usuario/repositorio.git mi-carpeta

<!-- Entrar al directorio clonado -->
cd repositorio

Trabajar con ramas (branches)

Leer explicación

Las ramas permiten desarrollar características de forma aislada sin afectar la rama principal. Son fundamentales para el trabajo colaborativo. 

            
<!-- Ver todas las ramas -->
git branch

<!-- Crear una nueva rama -->
git branch nueva-caracteristica

<!-- Cambiar a la nueva rama -->
git checkout nueva-caracteristica

<!-- Crear y cambiar a una rama en un solo comando -->
git checkout -b otra-rama

<!-- Hacer cambios y commits en la rama -->
git add .
git commit -m "Añadir nueva característica"

<!-- Volver a la rama main -->
git checkout main

<!-- Fusionar la rama de característica en main -->
git merge nueva-caracteristica

<!-- Eliminar rama después de fusionar -->
git branch -d nueva-caracteristica

Sincronizar cambios con GitHub

Leer explicación

Es importante mantener tu repositorio local sincronizado con el remoto, especialmente cuando trabajas en equipo. 

            
<!-- Descargar cambios del repositorio remoto sin fusionar -->
git fetch origin

<!-- Descargar y fusionar cambios automáticamente -->
git pull origin main

<!-- O simplemente (si ya configuraste upstream) -->
git pull

<!-- Subir tus cambios locales -->
git push origin main

<!-- Subir una rama específica -->
git push origin nombre-rama

Deshacer cambios

Leer explicación

Git ofrece varias formas de deshacer cambios dependiendo de en qué etapa se encuentren. 

            
<!-- Descartar cambios en un archivo no añadido -->
git checkout -- archivo.txt

<!-- Quitar archivo del staging area (mantiene cambios) -->
git reset archivo.txt

<!-- Deshacer último commit (mantiene cambios en working directory) -->
git reset --soft HEAD~1

<!-- Deshacer último commit y cambios -->
git reset --hard HEAD~1

<!-- Modificar el último commit (cambiar mensaje o añadir archivos) -->
git commit --amend -m "Nuevo mensaje"

<!-- Revertir un commit específico creando uno nuevo -->
git revert commit-hash

Ver historial y diferencias

Leer explicación

Estas herramientas te permiten explorar el historial de cambios y comparar versiones de archivos. 

            
<!-- Ver historial de commits -->
git log

<!-- Ver historial en una línea por commit -->
git log --oneline

<!-- Ver historial con gráfico de ramas -->
git log --graph --oneline --all

<!-- Ver cambios no añadidos al staging -->
git diff

<!-- Ver cambios en staging area -->
git diff --staged

<!-- Ver cambios en un archivo específico -->
git diff archivo.txt

<!-- Ver quién modificó cada línea de un archivo -->
git blame archivo.txt

Archivo .gitignore

Leer explicación

El archivo .gitignore especifica qué archivos o carpetas Git debe ignorar. Es esencial para no versionar archivos sensibles o innecesarios. 

            
<!-- Crear archivo .gitignore -->
touch .gitignore

<!-- Ejemplo de contenido de .gitignore -->
# Dependencias
node_modules/
vendor/

# Archivos de entorno
.env
.env.local

# Archivos del sistema
.DS_Store
Thumbs.db

# Archivos de compilación
dist/
build/
*.log

# IDEs
.vscode/
.idea/
*.swp

<!-- Añadir .gitignore al repositorio -->
git add .gitignore
git commit -m "Añadir .gitignore"

Fork y Pull Request

Leer explicación

Para contribuir a proyectos de otros, haces un fork (copia del repositorio en tu cuenta), realizas cambios y luego envías un Pull Request para que revisen e integren tus cambios. 

            
<!-- 1. Hacer fork desde GitHub.com (botón Fork) -->

<!-- 2. Clonar tu fork -->
git clone https://github.com/tu-usuario/proyecto-forked.git
cd proyecto-forked

<!-- 3. Añadir repositorio original como upstream -->
git remote add upstream https://github.com/usuario-original/proyecto.git

<!-- 4. Crear rama para tu contribución -->
git checkout -b mi-contribucion

<!-- 5. Hacer cambios y commit -->
git add .
git commit -m "Descripción de cambios"

<!-- 6. Subir rama a tu fork -->
git push origin mi-contribucion

<!-- 7. Crear Pull Request desde GitHub.com -->

<!-- 8. Sincronizar con el repositorio original -->
git fetch upstream
git checkout main
git merge upstream/main

Stash: Guardar cambios temporalmente

Leer explicación

El stash te permite guardar cambios temporalmente sin hacer commit, útil cuando necesitas cambiar de rama rápidamente. 

            
<!-- Guardar cambios actuales en stash -->
git stash

<!-- Guardar con mensaje descriptivo -->
git stash save "Trabajo en progreso de login"

<!-- Ver lista de stashes -->
git stash list

<!-- Aplicar el último stash y mantenerlo -->
git stash apply

<!-- Aplicar el último stash y eliminarlo -->
git stash pop

<!-- Aplicar stash específico -->
git stash apply stash@{2}

<!-- Eliminar último stash -->
git stash drop

<!-- Eliminar todos los stashes -->
git stash clear

Tags: Etiquetar versiones

Leer explicación

Los tags marcan puntos específicos en el historial como importantes, típicamente para versiones de lanzamiento (v1.0, v2.0, etc.). 

            
<!-- Crear tag ligero -->
git tag v1.0.0

<!-- Crear tag anotado con mensaje -->
git tag -a v1.0.0 -m "Primera versión estable"

<!-- Ver todos los tags -->
git tag

<!-- Ver información de un tag -->
git show v1.0.0

<!-- Subir tag específico -->
git push origin v1.0.0

<!-- Subir todos los tags -->
git push origin --tags

<!-- Eliminar tag local -->
git tag -d v1.0.0

<!-- Eliminar tag remoto -->
git push origin --delete v1.0.0

Resolver conflictos de merge

Leer explicación

Los conflictos ocurren cuando dos ramas modifican las mismas líneas de código. Git te pide que decidas qué cambios mantener. 

            
<!-- Intentar hacer merge -->
git merge otra-rama

<!-- Si hay conflictos, verás archivos marcados -->
git status

<!-- Abrir archivo con conflicto, verás marcadores: -->
<<<<<<< HEAD
Tu código actual
=======
Código de la otra rama
>>>>>>> otra-rama

<!-- Editar manualmente el archivo para resolver -->
<!-- Eliminar los marcadores y dejar el código correcto -->

<!-- Marcar conflicto como resuelto -->
git add archivo-resuelto.txt

<!-- Completar el merge -->
git commit -m "Resolver conflictos de merge"

<!-- Abortar merge si es necesario -->
git merge --abort

GitHub Actions - CI/CD básico

Leer explicación

GitHub Actions permite automatizar pruebas y despliegues. Los workflows se definen en archivos YAML en la carpeta .github/workflows/ 

            
<!-- Crear estructura de carpetas -->
mkdir -p .github/workflows

<!-- Crear archivo de workflow -->
touch .github/workflows/test.yml

<!-- Ejemplo de contenido test.yml: -->
name: Tests

on: [push, pull_request]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - name: Setup Node
        uses: actions/setup-node@v3
        with:
          node-version: '18'
      - run: npm install
      - run: npm test

<!-- Añadir y subir -->
git add .github/
git commit -m "Añadir GitHub Actions"
git push

Comandos útiles adicionales

Leer explicación

Comandos avanzados que mejoran tu productividad con Git y GitHub. 

            
<!-- Buscar en commits -->
git log --grep="palabra clave"

<!-- Encontrar qué commit introdujo un bug (búsqueda binaria) -->
git bisect start
git bisect bad
git bisect good commit-hash

<!-- Limpiar archivos no rastreados -->
git clean -n  # Ver qué se eliminará
git clean -f  # Eliminar archivos

<!-- Cambiar la URL del repositorio remoto -->
git remote set-url origin nueva-url

<!-- Ver información de un commit específico -->
git show commit-hash

<!-- Cherry-pick: aplicar commit específico de otra rama -->
git cherry-pick commit-hash

<!-- Rebase interactivo para limpiar historial -->
git rebase -i HEAD~3

<!-- Ver tamaño del repositorio -->
git count-objects -vH
